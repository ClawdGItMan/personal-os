# Personal OS — Plan 1A.6: PWA + Phase 1A Acceptance

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. This plan is executed **inline** by the lead agent (not a parallel wave): it is shared-file-heavy (root `layout.tsx`, `middleware.ts`) and tightly interdependent (manifest ↔ icons ↔ metadata ↔ middleware must agree), which per the 1A.2 lesson is the worst candidate for parallel agents in one tree. Steps use checkbox (`- [ ]`) syntax.

**Goal:** Make Personal OS an installable PWA — web manifest, app icons, theme-color + Apple web-app metadata, and a one-time iOS install prompt — and walk the spec §7 Phase 1A acceptance gate, targeting Lighthouse PWA ≥90.

**Architecture:** A static `public/manifest.json` (the spec's named location) is linked via the root layout's typed `metadata.manifest`; app icons are generated at build time by `next/og` `ImageResponse` route handlers served at `*.png` paths (zero new dependencies — no rasterizer is installed and none is needed). The auth middleware is widened to let the manifest through unauthenticated (icons already pass via the existing `.png` matcher exclusion) so Lighthouse/installers can fetch them from the login screen. A `"use client"` `<InstallPrompt>` shows iOS Safari share-sheet instructions once (localStorage-dismissed), since iOS has no `beforeinstallprompt` event.

**Tech Stack:** Next.js 16 App Router Metadata API (`Metadata`/`Viewport`, `MetadataRoute`), `next/og` `ImageResponse` (built into Next), React 19. **No new dependencies.**

**Spec reference:** `docs/superpowers/specs/2026-05-21-personal-os-design.md` §5.6 (PWA specifics — manifest fields, icons 180/192/512, theme/bg `#0E1014`, display standalone, start_url `/`, Apple splash meta, one-time iOS InstallPrompt) and §7 Phase 1A acceptance gate ("install to iPhone home screen → reload → data persists. Lighthouse PWA score ≥90"). Accessibility posture: spec §8.2 (semantic HTML + keyboard nav).

## Design facts (authoritative — from the codebase map)

- **Background/theme color is `#0E1014`** (`--os-bg` in `globals.css`; e2e already asserts computed `rgb(14, 16, 20)`). Accent (brand) is sage `#8FA67A`. Use these for manifest `theme_color`/`background_color` and the icon monogram.
- **No `public/` dir exists yet** — creating it for `manifest.json`. Favicon already lives at `src/app/favicon.ico` (file convention, middleware-excluded) — leave it.
- **Root layout** (`src/app/layout.tsx`) already uses the typed `metadata: Metadata` export and renders `<html data-theme="dark" className={fontVars}>` / `<body>`. There is **no `viewport` export yet** — `themeColor` belongs there in Next 16 (deprecated in `metadata`).
- **Middleware gotcha (critical):** `middleware.ts` matcher is `"/((?!_next/static|_next/image|favicon.ico|.*\\.(?:svg|png|jpg|jpeg|gif|webp)$).*)"`. Paths ending in `.png` are already excluded (icons are safe), but `manifest.json` is **not** — without a matcher change, an unauthenticated fetch of `/manifest.json` 302-redirects to `/login` and returns HTML, failing Lighthouse installability. **Must add `manifest.json` to the negative lookahead.**
- **No image rasterizer** (no sharp/ImageMagick/rsvg). Icons are generated by `next/og` `ImageResponse` route handlers — real PNGs at exact sizes, no install.
- **Only `/login` and `/callback` are unauthenticated HTML.** PWA e2e must therefore assert manifest/icon reachability via `page.request.get(...)` and check the `<link rel="manifest">`/theme-color on `/login`.
- **e2e:** `tests/e2e/*.spec.ts` (repo-root `tests/e2e`), `playwright.config.ts` `testDir: "./tests/e2e"`, baseURL from `BASE_URL`/`PORT`, `webServer: pnpm dev` (reuses a running server locally).

## Task 1: App-icon route handlers (build-time PNGs via next/og)

**Files:** Create `src/app/icons/[icon]/route.tsx`.

- [ ] Implement a dynamic route that maps a filename → size/maskable and returns an `ImageResponse`. The path ends in `.png`, so the existing middleware matcher already serves it unauthenticated.

```tsx
import { ImageResponse } from "next/og";

const ICONS: Record<string, { size: number; maskable: boolean }> = {
  "icon-180.png": { size: 180, maskable: false },
  "icon-192.png": { size: 192, maskable: false },
  "icon-512.png": { size: 512, maskable: false },
  "icon-512-maskable.png": { size: 512, maskable: true },
};

export function generateStaticParams() {
  return Object.keys(ICONS).map((icon) => ({ icon }));
}

export async function GET(_req: Request, { params }: { params: Promise<{ icon: string }> }) {
  const { icon } = await params;
  const cfg = ICONS[icon];
  if (!cfg) return new Response("Not found", { status: 404 });
  // Maskable icons keep the glyph inside the central ~60% safe zone; the bg fills the canvas.
  const glyph = Math.round(cfg.size * (cfg.maskable ? 0.34 : 0.46));
  return new ImageResponse(
    (
      <div
        style={{
          width: "100%",
          height: "100%",
          display: "flex",
          alignItems: "center",
          justifyContent: "center",
          background: "#0E1014",
          color: "#8FA67A",
          fontFamily: "monospace",
          fontWeight: 700,
          fontSize: glyph,
          letterSpacing: "-0.04em",
        }}
      >
        OS
      </div>
    ),
    { width: cfg.size, height: cfg.size },
  );
}
```
